---
name: Repeat event bookings
description: Why repeat guest bookings require a separate, explicit booking flow rather than resetting a completed payment.
---

Allow additional in-person and online event bookings from the same browser through an explicit new-booking action; keep previous booking access available.

**Why:** The user expects to book again from the landing page, not be permanently limited to the first booking. Automatically clearing a paid booking would risk duplicate charges and losing access to its approval or VIP upgrade.

**How to apply:** Treat an additional seat as a separate purchase, explain that it incurs another payment, retain access to previous bookings, and resolve uncertain payment results before changing the active booking.
